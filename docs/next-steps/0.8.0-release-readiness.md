## Next steps

### 1. Align CI with the project runtime

Current problem: `.github/workflows/tests.yml` still installs pnpm 10 and Node 22. It also omits `HOST` and `PORT`.

A clean-checkout test run with the current CI environment produced:

```text
Error: getaddrinfo ENOTFOUND library
Tests 217 passed, 1 failed (218)
```

The ignored local `.env.test` masks this problem by defining `HOST=localhost` and `PORT=3333`.

Required changes:

- Use Node `24.18.0` or read the version from `.nvmrc`.
- Use pnpm `11.15.1`.
- Set `HOST=127.0.0.1` and `PORT=3333` for the test job.
- Retain `NODE_ENV=test`, `LOG_LEVEL=info`, `APP_KEY`, `SESSION_DRIVER=memory`, and `MB_APP_CONTACT_EMAIL`.
- Use `pnpm install --frozen-lockfile` in CI.

Acceptance:

- The clean-checkout CI command passes all 218 tests without relying on `.env.test`.

### 2. Align the release container with Node 24 and pnpm 11

Current problems in `Dockerfile`:

- Base image is `node:jod-alpine3.23` (Node 22), while `.nvmrc` is `24.18.0`.
- Dependency stages copy only `package.json` and `pnpm-lock.yaml`.
- `pnpm-workspace.yaml`, which owns pnpm 11 overrides and `allowBuilds`, is absent during installation.

Required changes:

- Use a Node 24/Krypton image pinned consistently with `.nvmrc`.
- Copy `pnpm-workspace.yaml` into both dependency stages before running pnpm.
- Ensure the production dependency install uses the same pnpm configuration and frozen lockfile.
- Build both `linux/amd64` and `linux/arm64` images as the release workflow expects.

Acceptance:

- A clean multi-stage Docker build completes.
- The resulting image starts and serves `/library/listen-later`.
- The Docker build must be rerun when a Docker daemon is available; the readiness session could not connect to the local OrbStack socket.

### 3. Pin pnpm 11.15.1 for reproducibility

Current problem: the project configuration is pnpm 11-specific, but `package.json` does not declare the package-manager version. Docker currently relies on whichever pnpm Corepack activates.

Required change:

```json
"packageManager": "pnpm@11.15.1"
```

Confirm the exact Corepack workflow supported by the selected Node 24 image.

Acceptance:

- Local, CI, and Docker installs all report pnpm `11.15.1`.
- `pnpm install --frozen-lockfile` succeeds in all three environments.

### 4. Repair the Playwright suite

Observed result under the correct clean environment:

```text
4 passed
10 failed
```

Failure classes in `tests/e2e/listen-later.spec.ts`:

- Page test expects `/Listen Later/`, but production title is `MusicKeeper`.
- `getByRole('button', { name: 'Add' })` also matches `Added`; use an exact or scoped locator.
- `getByLabel('Title')` matches the search combobox and dialog edit field; scope to the dialog or use an exact role/label.
- The delete test expects an existing item without creating its own state.

Do not merely weaken assertions. Each E2E test must establish its own state and verify the intended user behavior.

Acceptance:

- `pnpm test:e2e` passes all 14 tests from a clean checkout with an isolated browser context.
- Tests remain valid with `fullyParallel: true`.

Suggested skill: `diagnose` for the failing-test loop.

### 5. Make lint a usable release gate

Observed result from `pnpm lint` in the clean checkout:

```text

```

Most failures are Prettier and filename-style violations in generated UI components. There are also substantive diagnostics, including `@typescript-eslint/no-shadow` in `src/infrastructure/pwa/cache_config.ts`.

Decision required:

- Either fix and format the full tracked tree, including generated UI files, or
- Narrow the lint command/configuration to maintained source files and explicitly exclude generated/vendor-style UI output.

Do not hide substantive TypeScript/ESLint errors with blanket ignores.

Acceptance:

- The chosen release lint command exits zero in a clean checkout.
- CI runs that exact command.
- Non-formatting diagnostics in maintained application code are resolved.
